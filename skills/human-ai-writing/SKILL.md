# 人机共写

让作者的真实经验和判断得到清楚表达。可独立使用；安装了 collaboration-methods 时，可按需要结合其通用协作方法，无强制依赖。

## 根据起点推进

- 只有念头：先提出值得写的主张候选，指出各自需要的材料；问题聚焦到能改变主线的信息。
- 已有素材：提炼其中的主张、具体场景、证据和适用条件；把作者明确说过的与编辑推断区分开。
- 已有初稿：先按用户要求修改；仅当主线或事实问题影响目标时，指出并处理。
- 只是改句子、翻译或缩短：直接交付，不强制采访或等待提纲确认。

## 共写方法

1. 理解读者、阅读后的预期变化、篇幅和渠道。能推断的先采用并简短注明；作者的审美和探索目标也可以是成功标准。
2. 从原始经历、原声、笔记和资料提炼主张。问到具体发生了什么、为什么作此判断、什么情况不适用；不要为了完整性追问无关背景。
3. 提出清楚的主线，让每段推进理解。多种方向确实会改变文章时，帮助作者取舍；素材充分或用户要求直接成稿时，直接写。
4. 使用适合任务的方法：采访补细节，反例检查论证，编辑消除重复，目标读者检查理解门槛。不要只模拟“专家口吻”。
5. 核查可验证事实和引用，给出可追溯来源；未经核查的关键断言明确标记待核。不得虚构个人经历、引述、数字、客户案例或作者立场。
6. 把作者反馈理解为对主张、语气、边界或结构的校准，定向修改，不默认推翻全文。对公开或重要文章，在条件允许时征求真实读者反馈；未获取时注明尚未验证，不编造反馈。

保留具体经验、自然语气和有辨识度的表达。除非用户要求，不为了“专业”加入术语或把所有文章套进同一种结构。

## 交付与接续

按用户所需交付成稿或当前阶段成果，附少量必要的待核事实与关键取舍。不要把采访记录、策划分析全部塞进正文。

跨 Agent 接续时，交接目标读者、主张、作者确认的立场、素材出处、当前稿件位置、待核事实及下一步。作者确认文章方向不等于授权公开发布。

需要开场示例或素材不足时的处理方式，读取 [examples.md](references/examples.md)。
