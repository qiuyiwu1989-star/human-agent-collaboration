# 多 Agent 与跨会话交接

方法库提供共享方法，不假设不同 Agent 自动共享记忆、文件、工具或权限。协调方式服从当前环境和用户授权，不自动启动 Agent 或新会话。

## 最小交接包

仅保留与下一位执行者有关的信息，可直接写在消息中；任务较长且用户授权落盘时，再保存为任务文件。

```text
目标及成功标准：
用户明确约束、授权与禁止事项：
当前产物位置和版本/提交：
已确认决定（谁确认）：
原始材料与证据位置：
已执行的验证、结果及其覆盖范围：
推断、待核事实与未解决问题：
下一步、负责人、依赖：
```

接手者先核对可访问材料及当前版本；访问不到就说明，不能把交接描述当成自己完成了验证。不要传递凭据，不把私有任务材料提交到公开方法库。

## 真正需要并行时

- 按交付或不确定性拆分，例如实现与测试、资料核查与结构审阅；明确接口和输出位置。
- 同一文件或决策指定一个整合负责人，避免多个 Agent 同时覆盖。
- 独立审阅者获取目标、标准、实际材料和必要上下文；避免先告诉它“应该通过”。保留其发现和验证局限。
- 汇总时记录冲突、证据及处理理由。多个 Agent 表态相同不构成独立事实证据。
- 需要用户确认的取舍由协调者汇总，避免不同 Agent 重复发问；已确认的约束随交接传递。

## 经验进入公共库的条件

从真实案例提取可复用的方法，删除个人资料、私有路径、项目数据和凭据。说明适用条件及失败边界；单次有效不自动成为所有任务的固定规则。只有当前任务授权维护公共库时才提交更新，普通任务的交接不等于开源授权。
